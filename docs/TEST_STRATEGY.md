# Test strategy

Decision record: [ADR 0006](adr/0006-testing-policy.md).

## Levels

| Level | Scope | Location | Runs |
| --- | --- | --- | --- |
| Unit | Pure logic and modules with fakes | `*/test/*.test.ts` | Every pull request |
| Integration | Real Postgres, queues and webhooks | `*/test/*.test.ts` | Every pull request |
| End to end | Dashboard flows in a browser (from M7) | To be added in M7 | Every pull request |
| Eval | Agent behaviour against scenarios (from M2) | `evals/` | Gate on agent changes |

Database tests need `DATABASE_URL`. They create and drop their own database, so they never touch development data. **Without `DATABASE_URL` they're skipped, and the coverage gate then fails on `packages/db`.** That is deliberate. Other packages must reach 100% through their own tests, not through a database test that happens to call them.

## Coverage policy

`npm run test:coverage` requires 100% lines, branches, functions and statements, per file, for `apps/*/src` and `packages/*/src`.

**Exclusions** (defined in `vitest.config.ts`):

| Path | Reason |
| --- | --- |
| `packages/db/src/generated/**` | Generated by Prisma |
| `apps/api/src/server.ts` | Process entrypoint with wiring only; exercised by the CI image smoke test |

Adding an exclusion needs a reason here and in `vitest.config.ts`, and review. Before adding one, try moving the logic out of the entrypoint. Prefer that to `v8 ignore` comments, which aren't allowed for logic.

**Outside the coverage scope:**

| Path | How it's checked instead |
| --- | --- |
| `scripts/` | Run by `audit:tokens` and `audit:units` in CI |
| `design/` | Exercised through `audit:tokens` |
| `packages/db/scripts/seed.ts` | CI runs the seed twice to prove it's idempotent |
| `deploy/server/` | Legacy; removed at AWS cutover |

## Writing good tests

- Coverage shows that code ran, not that it's correct. Each test should fail if the behaviour breaks.
- Test behaviour through public functions, not private details.
- Every guardrail in [Requirements](REQUIREMENTS.md) has a test that doesn't depend on model output.
- Prefer small fakes through injected interfaces. Avoid real timers: use `vi.useFakeTimers()`.
- A bug fix starts with a failing test.

## Evals

Evals check agent behaviour, which coverage can't measure. They arrive in M2 and become a CI gate in M8 (EV-1 to EV-6). Failures seen in production traces become new scenarios.

## Proving a gate works

A new gate must be shown to fail on a planted violation before it's trusted.
